# 4399 五子棋人机对局

## Problem Statement

用户想在 Codex 等待工作时，从 4399 游戏馆打开一局五子棋，和自己选定的 Codex 模型对弈。方案 B 的界面已经定稿，原型可以体验开局和悔棋，正式版本需要让真实模型根据最新棋局落子，并按本局配置使用指定的思考强度。

## Solution

从游戏馆进入五子棋，先选棋盘尺寸、对手模型、思考强度和先手，然后开始一局。界面延续方案 B 的亮色配置浮层和简洁棋盘。由本地游戏服务维护棋局，独立的 Codex 对战会话根据固定规则和每手的棋局快照选择落点。对局页显示本局配置、双方棋色、回合或结果，以及悔棋和重新开始。

## User Stories

1. 作为玩家，我想从游戏馆的五子棋卡片进入配置页，以便开始一局。
2. 作为玩家，我想选择 9、13 或 15 路棋盘，以便按屏幕和空闲时间决定对局大小。
3. 作为玩家，我想从本机 Codex 可用的模型中选对手，以便和指定模型对弈。
4. 作为玩家，我想只看到所选模型支持的思考强度，以便选到有效配置。
5. 作为玩家，我想换模型时保留受支持的强度，否则使用新模型的默认档，以便少做重复选择。
6. 作为玩家，我想直接使用默认模型及其默认强度开始，以便快速开局。
7. 作为玩家，我想选择自己先下、AI 先下或随机先手，以便决定执黑还是执白。
8. 作为玩家，我想在对局中看到双方棋色和本局模型配置，以便确认当前对手。
9. 作为玩家，我想点击空交叉点落子，并看到 AI 思考及落子，以便自然地交替对弈。
10. 作为玩家，我想一眼看出最近一手，以便跟上棋局。
11. 作为玩家，我想在形成五连或棋盘下满时看到结果，以便知道对局已经结束。
12. 作为玩家，我想撤回自己最近一手及 AI 的回应，以便重新选择落点。
13. 作为玩家，我想在 AI 思考时悔棋，以便收回刚落下的一手而不受迟到的回应影响。
14. 作为后手玩家，我想悔棋时保留 AI 的开局第一手，以便回到正确的轮次。
15. 作为玩家，我想在胜负已定后也能悔棋，以便复盘关键一步。
16. 作为玩家，我想点重新开始返回配置并沿用本局选择，以便调整下一局。
17. 作为玩家，我想在配置页返回当前对局，以便取消重新开始。
18. 作为玩家，我想在 AI 请求失败时看到可重试的状态，以便保留棋局继续玩。
19. 作为玩家，我想在 Codex 登录不可用时看到可操作的提示，以便恢复模型列表。
20. 作为玩家，我想在右侧窄栏看到完整棋盘和操作，以便边等工作边玩。
21. 作为插件使用者，我想用本机 Codex 的登录配置对弈，以便用现有账号的模型能力。
22. 作为维护者，我想将背景和规则集中维护，以便调整 AI 的对战指令而不改棋盘逻辑。

## Implementation Decisions

- 沿用方案 B 定稿原型 `51a84e3` 的视图。默认 15 路和玩家先手，模型及思考强度采用 Codex 可用目录提供的默认值。继续沿用 4399 的本地启动方式和回环地址。
- 本地 Node 服务通过标准输入输出连接 Codex App Server。用 `model/list` 获取模型和支持的强度，开局时校验组合。每局创建独立的临时对战会话，使用本机 Codex 的登录方式。
- 创建对战会话时传入固定的 `developerInstructions`，包括角色、自由五子棋规则、坐标和输出约定。每个 AI 回合通过 `turn/start` 传入棋盘尺寸、执色及完整棋谱，指定本局模型与思考强度，使用 `outputSchema` 约束为行列坐标。
- 游戏服务维护内存中的权威棋局。行列从左上角零基编号，黑棋先手。仅在轮到对应一方且落点合法时更新棋局。横、竖、斜五子及以上获胜，不设禁手，棋盘下满且无人获胜为平局。
- 悔棋退回到玩家最近落子之前。配置新局时暂停现局，确认开局才替换。悔棋、暂停和换局使在途请求失效，取消请求并校验回复所属棋局及回合。继续现局时如仍轮到 AI，按现有棋谱重新请求。
- AI 出错、超时或返回非法落点时保留棋局并允许重试。模型目录读取失败时提供重试入口。页面与本地服务通过同源 JSON 接口交互。

## Testing Decisions

- 延续现有 HTTP 服务测试，从游戏接口验证模型配置、对局状态和用户动作。替换模型调用边界以控制 AI 回复，检查非法坐标及悔棋、换局后的迟到回复。
- 在本机已登录的 Codex 上验证模型目录和至少一手真实模型落子，确认传入的推理强度能被接受。
- 在 Codex 右侧浏览器体验从游戏馆进入、配置模型与强度、落子、悔棋和重新开始。关注可见行为及棋局结果。

## Out of Scope

- 其他游戏、多人联网、历史对局存档、用户自定义提示词编辑器、独立棋力评估。

## Further Notes

- 原型保留在 `codex/prototype-gomoku` 分支。规则采用定稿原型的自由五子棋约定。
- 接口参考 [Codex App Server](https://learn.chatgpt.com/docs/app-server)。
