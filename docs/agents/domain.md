# Domain Docs

This repository uses a single domain context.

- Before exploring domain behavior, read the root `GLOSSARY.md` if present.
- Before proposing or changing architecture, read relevant records in `docs/adr/` if present.
- Use the glossary terms in specs, tickets, code discussions, and test names. If a change revisits an ADR, name that record and explain the conflict.
- Create glossary entries and ADRs when decisions are made. If either location is absent, proceed.
